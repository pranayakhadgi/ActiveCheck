# Decision log

Format: **Decision**: why · alternatives considered · trade-off

- **TypeScript everywhere**: one language across loader, API and UI makes it easier to explain · Python loader · slightly worse data tooling
- **Raw SQL instead of an ORM**: shows SQL skill and keeps queries visible · Prisma/Drizzle · more boilerplate
- **Index funds stand in for indexes**: free public data from the same source · licensed index data · small tracking differences and cash drag
- **Equity-only rescaled weights**: active share is defined over stock picks; cash would inflate it · raw pctVal · excluded % must be shown
- **Scaffolded with `create-next-app` in a temp dir, then moved in**: the folder name `activeChecek` has a capital letter, which npm rejects as a package name · renaming the folder · one-off manual move; `package.json` is named `activecheck`
- **shadcn/ui `radix` base, `nova` preset**: the current CLI has no `--base-color` flag, and radix+nova is the classic shadcn setup (Radix primitives, lucide icons) · the newer `base` component library · palette is then overwritten by hand with the DESIGN.md tokens
- **Theme tokens defined as CSS variables on `:root` / `.dark`, plus a `prefers-color-scheme` block**: there is no theme toggle yet, so dark mode has to follow the OS · shipping `next-themes` now · Tailwind `dark:` utilities do not fire from the media query, so colour must come from the variables, not from `dark:` classes
- **Signal hues lightened in dark mode** (amber `#F59E0B`, green `#4ADE80`, red `#F87171`): the light-mode values fail WCAG AA on `#0C0A09` · keeping the exact hex values · same hues, different lightness
- **`npm run typecheck` runs `next typegen` first**: Next 16 generates `LayoutProps`/`PageProps` into `.next/types`, so bare `tsc --noEmit` fails on a clean checkout (as in CI) · hand-writing the prop types · typecheck depends on the Next CLI
- **`@types/node` bumped to v24**: Vitest 5 peer-requires `^22 || >=24`, and the local Node is v24 · `--legacy-peer-deps` · none
- **Vitest config as `vitest.config.mts`**: the package is CommonJS, so a `.ts` config warns under Vite's native config loader · `"type": "module"` in package.json · none
- **Benchmarks are just funds with `is_index = true`, not their own tables**: index funds already stand in for indexes and file the same N-PORT forms, so a separate `benchmarks`/`benchmark_holdings` pair would duplicate `funds`/`holdings` and need a second loader · the research proposal's dedicated benchmark tables · benchmark weights inherit index-fund cash drag, which we already accepted
- **No `share_classes` table in the MVP**: N-PORT reports holdings at series level, so classes only differ by expense ratio; `funds.ticker` + `funds.expense_ratio` name the one class we quote · modelling every class now · switching share class later means a migration
- **Expense ratio stored on `funds` with a single `er_as_of` date, not a history table**: the MVP shows one current number next to one report period, so versioned ERs would be unused rows · `expense_ratios(share_class_id, as_of)` · no historical recomputation until we add it
- **No `results` table; analytics computed on read**: `lib/analytics/` is pure and runs over a few thousand rows in milliseconds, and a cache would need invalidation on every ER or benchmark change · persisting active share per (filing, benchmark) · repeated page loads recompute
- **`filings.accession_no UNIQUE` plus `UNIQUE (fund_id, report_period)`**: the accession number makes `npm run load` re-runnable, and the second constraint stops an amended filing from double-counting a month · accession number alone · an N-PORT/A must delete-and-replace the original, not just insert
- **`holdings.match_key` column, unique per filing**: the CUSIP→ISIN→normalized-name fallback is resolved once at load and stored, so matching is a plain join and slice aggregation bugs fail loudly instead of double-counting · resolving the fallback in SQL at query time · re-running the matching rules means reloading filings
- **`asset_cat` as a CHECK-constrained TEXT column**: keeps the five buckets visible in the schema and greppable in SQL without a Postgres enum's migration cost when we add one · enum type · no type safety beyond the CHECK
- **Weights stored as reported (`pct_val`), rescaled in code**: `lib/analytics/` must stay the single place the equity-only rescale happens, and the excluded % is derived from the same rows · a precomputed `pct_rescaled` column · every read rescales
- **Migrations tracked in `schema_migrations(name)`, one transaction per file**: filename is the version, a partly-applied file rolls back whole · a numeric version column or a migration library · no down-migrations; fix forward with a new file
- **`lib/db.ts` caches the postgres.js client on `globalThis` outside production**: Next dev hot-reloads modules and would otherwise open a new pool per reload · a new client per import · a stale pool survives a reload that changes connection options
- **DATE columns parsed as `YYYY-MM-DD` strings**: report periods are calendar dates, and the default JS `Date` parse shifts them a day in negative-offset timezones · `Date` objects with UTC formatting at each call site · dates are strings, not `Date`, throughout
- **Fixture funds are IVV/IVW/IVE (index) and FCNTX/TRBCX/DODGX (active)**: the three iShares S&P 500 series are the benchmark set `DESIGN.md` compares against, and Contrafund, Blue Chip Growth and Dodge & Cox Stock are large, long-lived active large-cap funds whose styles span growth, growth-at-scale and value, so `closestIndex` has something to choose between · the five funds the research notes asked for (it could not verify identifiers for any of them) · three active funds is a thin sample, and none is a closet indexer, so we still need a low-active-share fixture
- **Tickers resolved through `company_tickers_mf.json`, not hand-entered CIKs**: one SEC file maps ticker → (cik, seriesId, classId), so the identifiers the research notes left **unverified** are looked up rather than guessed · pasting CIKs from the research notes · the file is a full download (~245 KB) for six lookups
- **Latest NPORT-P found via the per-series EDGAR atom feed**: `submissions/CIK##########.json` carries no series information, so for a trust like iShares (hundreds of series) it cannot say which filing is our fund's; `browse-edgar?CIK=S000xxxxxx&type=NPORT-P&output=atom` filters by series server-side · downloading every trust NPORT-P and reading each `seriesId` · depends on the legacy browse-edgar CGI rather than the modern JSON API
- **Fixture fetch skips NPORT-P/A amendments**: an amendment is a delete-and-replace of the original at *load* time, so mixing one into the fixtures would test loader behaviour from a parser fixture · always taking the newest entry · a fixture can be superseded by an amendment we ignore
- **`pctVal` is a percentage, already summing to ~100**: verified across all six fixtures (99.86–100.37); the research note claiming it needs ×100 was wrong · trusting the note · none, but `lib/analytics/` must not multiply again
- **`parseNport` takes XML text, never a path or URL**: keeps fetching in `lib/edgar/` and lets tests run with no network and no I/O in the parser · a `parseNportFile(path)` convenience · callers read the file themselves
- **`fast-xml-parser` with `parseTagValue: false`**: `pctVal` and `valUSD` are filed with more significant digits than a JS number keeps, so every field is converted explicitly and a non-numeric value throws instead of arriving as `NaN` · the parser's own number coercion, or `xml2js` · a little more conversion code
- **`isArray` forces `invstOrSec` and `identifiers/other` to arrays**: a single-holding filing would otherwise parse to an object, and IVV files 509 `other` identifiers across 508 holdings, so neither is reliably singular · defensive `Array.isArray` checks at each call site · the parser config has to list every repeatable element
- **Unrecognised or missing `assetCat` buckets to `OTHER`, not an error**: one IVV holding files no `assetCat` at all, and `OTHER` is excluded from equity weights and counted in the excluded %, which is the conservative outcome · throwing on an unknown category · a new SEC category would be silently excluded rather than flagged
- **Dates validated by a UTC round-trip, still returned as strings**: catches a filed `2026-02-31` while keeping the no-timezone-shift rule the DATE columns already follow · a regex shape check alone · the check allocates a `Date` it then discards
- **`repPdDate`, not `repPdEnd`, is the holdings date**: `repPdEnd` is the fiscal-period end and runs later (IVV: `repPdDate` 2026-06-30 vs `repPdEnd` 2027-03-31), so it would mislabel every number on the fund page · `repPdEnd` · a test asserts `reportDate <= repPdEnd` on every fixture
- **CUSIP placeholders (`N/A`, `000000000`, empty) normalised to `null` at parse time**: 148 of 428 Contrafund holdings file `N/A` (foreign equities that do carry an ISIN), and a literal `"N/A"` match key would collide every one of them into a single fake security · keeping the raw string and filtering during matching · the raw filed value is not preserved
- **Active share computed as `max(total overweight, total underweight)`, not literally `½ Σ|Δw|`**: the two are identical whenever both weight vectors sum to 1, but the half-sum silently returns 0.5 for a fund with no equity holdings at all, where the honest answer is 1 (it shares nothing with the index) · the literal half-sum with a separate emptiness guard · the code no longer reads exactly like the formula in `CLAUDE.md`, so the comment carries the proof
- **Only `EC` (common equity) counts as equity; preferred `EP` is excluded**: index funds hold the common line, so a preferred position would be a permanent unmatched "bet" against a benchmark that cannot hold it · treating `EP` as equity · preferred-heavy funds show a larger excluded %
- **`assetCat` → `AssetClass` map lives in `lib/nport/portfolio.ts`**: the filer's N-PORT vocabulary is interpreted in exactly one pure place, so `lib/analytics/` and the `holdings.asset_cat` CHECK share one five-bucket vocabulary · analytics importing `AssetCat` directly · one more hop between parser and analytics
- **Matching runs as three portfolio-wide passes (CUSIP, then ISIN, then name), not a per-holding cascade**: a per-holding cascade lets an early holding's name match claim a benchmark security that a later holding's CUSIP match needs, which silently assigns the wrong benchmark weight · per-holding fallback · three passes over the portfolio instead of one
- **A benchmark security can be claimed by at most one fund security, and an identifier held by two benchmark securities is dropped as ambiguous**: both rules stop benchmark weight being counted twice, which would push active share below its true value · first-match-wins on ambiguity · an ambiguous CUSIP falls through to the name pass rather than resolving
- **Name normalization drops legal-form tokens anywhere in the name, keeps share-class tokens, and only ever matches on exact equality**: filers write "Alphabet Inc Class A" and "Alphabet Class A" for the same security but GOOG and GOOGL are genuinely different ones · token-overlap scoring as the research notes suggest · near-miss names go unmatched and land in the unmatched %
- **Excluded % is measured against Σ|pctVal| as filed, not against `netAssets`**: the holdings rows are the only thing the analytics layer sees, and filings sum to 99.86–100.37 rather than exactly 100 · dividing by `netAssets` · the denominator is the filed total, so a filing that omits lines understates the excluded %
- **`effectiveActiveFee` returns `undefined` for active share ≤ 0 and never clamps**: with nothing active the fee gap buys nothing, so the ratio is undefined rather than Infinity; a negative fee (fund cheaper than its index) and a fee amplified by a tiny active share are both real signals · clamping or smoothing · the UI must flag the amplified regime, which `isFeeReliable` (`UNRELIABLE_ACTIVE_SHARE = 0.2`) exists for
- **Every sort in `lib/analytics/` breaks ties on the identity key or ticker**: results are computed on read, so an unstable sort would make the fund page reshuffle between loads and look like the data changed · natural sort order · a little extra comparator code
- **Known gap: fund and benchmark filings are compared across different report periods**: the fixtures pair FCNTX at 2026-03-31 with IVV at 2026-06-30, which inflates active share slightly (research notes edge case #3); both dates are shown, but nothing yet picks the nearest benchmark vintage · refusing to compare mismatched periods · active share is a small overestimate until the loader selects by period
- **Fixture provenance recorded in `fixtures/nport/manifest.json`**: `primary_doc.xml` carries no accession number, and the accession number is the loader's dedupe key, so the fixture fetcher writes CIK, series, accession, filing date, report period and source URL beside the XML instead of the loader inventing a key from the filename · re-fetching the atom feed at load time · the manifest can drift from the XML if either is edited by hand
- **A cached fixture's accession is resolved by matching `repPdDate`, not by taking the newest NPORT-P**: IVE's cached fixture turned out to be the May filing while a newer one had landed, so "newest" would have labelled the file with an accession number that is not the document on disk · always taking the feed's first entry, or re-downloading · resolving costs one extra fetch per fixture and fails loudly if the fixture predates the feed window
- **`data/expense_ratios.csv` ships with every expense ratio marked `unverified`**: `docs/research/perplexity.md` supplies no fee values at all — §5 explicitly declines to give a verified net expense ratio for any active fund and §4 marks even the MFRR column name unverified — so the ratios are placeholders carrying each fund's publicly quoted headline fee · leaving the column empty and showing no effective active fee · the headline number on every fund page is currently illustrative, which `funds.er_verified` forces the UI to say out loud
- **Reversal: there *is* a `results` table now** (002): 001 argued analytics could run on read because `lib/analytics/` is pure and fast. That held for a route handler, not for a server component — rendering three numbers meant pulling the fund's holdings plus all three benchmarks' (~1,900 rows) on every request. `results` and `result_weights` are a materialisation the loader owns and replaces wholesale, never a second source of truth · recomputing per request, or caching in the framework · a stale result survives an expense-ratio edit until `npm run load` runs again
- **Comparisons are stored for every benchmark, not only the closest**: the comparison table on the fund page shows all three, and storing only the winner would mean recomputing the other two to render one table · storing the closest row only · 3 result rows and up to 60 weight rows per fund instead of 1 and 20
- **`results_one_closest_idx` is a partial unique index, not a convention**: the fund page selects the headline figures by `is_closest`, so two winners would render an arbitrary one · trusting the loader to set exactly one · the loader must delete a filing's results before inserting new ones, which it does
- **Index funds are measured against each other too**: IVV/IVW/IVE file the same form and are already loaded, so comparing them costs nothing and finally gives the app the low-active-share example the fixture set was missing (IVV is 33.7% active against IVW) · benchmarking active funds only · an index fund's page is labelled "closet indexer", which is true but reads oddly for a fund that is the index
- **Holdings are unique per (filing, match_key, **asset_cat**)** (003): Contrafund files both a common and a preferred line for 14 private companies (SpaceX, Stripe, Gusto), none with a CUSIP or ISIN, so both fall through to the normalized-name key and collide. Aggregating them together would fold a preferred stake into the common line, the exact thing excluding `EP` from equity prevents · a synthetic suffix on the match key · the match key alone is no longer unique within a filing
- **`npm run load` deletes and re-inserts a filing's holdings rather than upserting them**: an interrupted load repairs itself and a removed line cannot linger · upsert plus a delete of stragglers · surrogate ids advance on every run, so `npm run db:summary` proves re-runnability with a content digest that hashes tickers, accession numbers and weights rather than ids
- **The loader reads holdings back out of Postgres before computing results**: the numbers on the fund page are then derived from exactly the rows the page cites underneath them, so a storage bug cannot hide behind in-memory parse output · computing from the parsed filing still in memory · one extra round trip per filing
- **60% is the closet-indexer line, and it only changes a word and a colour**: Cremers & Petajisto describe 20–60% as the low range and later studies use 60% as the cutoff (perplexity.md §6) · 80% for "high active" · a fund at 59.9% is labelled differently from one at 60.1%, which is why the threshold never touches a number
- **Verdict wording lives in `lib/verdict.ts`, outside `lib/analytics/`**: it is presentation — analytics produces numbers, this decides how to say them — but it is still pure, so the sentence is unit-tested rather than reviewed by eye · building the sentence inline in the page · one more module between data and JSX
- **Over/underweight tables are stacked, not side by side**: at the 960px max width two five-column tables clip the difference column and its diverging bar, which are the point of the tables · a two-column grid with the bar dropped · the page is longer
- **`CommandItem` wraps a `Link` without `asChild`**: the shadcn item always renders a trailing check icon after its children, so slotting hands Radix two children and the build fails at prerender · a router push on `onSelect` · the unused check icon is hidden with a class instead of removed
- **The hero's proof element reads through `getFundReport`, not a new query**: the landing page's one worked example is then derived from exactly the rows the fund page it links to renders, so the card can never quote a number the product does not actually produce · a narrow `getHeroProof` SQL select · the hero also pulls the fund's ~20 stored weight rows, which it does not render
- **The hero fund is pinned to TRBCX (`S000002069`) by series id**: it is the only loaded active fund whose filing shares a report period with its closest index, so the card carries no mismatched-period caveat competing with the numbers for attention · picking the lowest- or highest-active-share fund at render time · a reload that changes TRBCX's vintage can introduce the caveat, which the card renders rather than hides
- **The illustrative fallback names no fund and invents no ticker**: `docs/brand-and-hero.md` bans both inventing tickers and attaching a real fund's name to numbers it did not produce, so the fallback is "An actively managed large-cap fund" vs "Its closest available index fund" · a plausible fake ticker · the fallback's verdict sentence is written by hand instead of by `verdict()`, which needs a ticker to name
- **The illustrative fee is computed by `effectiveActiveFee`, not typed in**: the fallback card exists to demonstrate the arithmetic, so it runs the real formula over round placeholder inputs · a hard-coded string · the constants and the sentence have to stay in step by hand
- **Hero motion is `motion-safe:` Tailwind utilities over `tw-animate-css`, not a keyframe of our own**: `motion-safe` compiles to `prefers-reduced-motion: no-preference`, so the reduced-motion guard is in the class list and cannot be forgotten, and under `reduce` no animation property is emitted at all · a hand-written `@keyframes` in `globals.css` with a media query · the entrance is spelled out in five utility classes
- **The secondary CTA is a `variant="link"` Button tinted `--color-link`**: the shadcn link variant is ink (`text-primary`), and DESIGN.md reserves the blue accent for links and focus rings, which is what this is · leaving it ink, or making it an `outline` button · one className override on a shadcn variant
- **`/methodology` restates `CLAUDE.md` and `docs/decisions.md` rather than adding to them**: every other page links here instead of re-explaining the method in slightly different words, per the brand rules · explaining the formulas inline on the landing page · the formulas now live in three places and must be changed together
- **`id="find-a-fund"` sits on the section, not on its (previously `sr-only`) heading**: the hero's primary CTA scrolls here, and anchoring to a visually hidden heading dropped the reader in past the heading with no idea what had just happened · keeping the anchor on the `h2` · the heading is now visible, which the brief's section list wanted anyway
- **The landing page's jargon tooltips go through one local `Term` component**: three terms are defined in a single paragraph, and inlining `Tooltip`/`TooltipTrigger`/`TooltipContent` three times buried the sentence in markup · repeating the shadcn trio per term · a component that exists only for this page
- **`<meta description>`, the hero and the "What ActiveCheck measures" section all carry the product statement verbatim**: `docs/brand-and-hero.md` fixes that sentence, and three near-variants of it is how a product starts claiming it "evaluates" funds · a shorter marketing description for search results · the sentence is duplicated in two files and must be changed in both
- **The final CTA repeats the hero's action rather than introducing a new one**: the brand rules allow exactly one primary action, so the page closes by sending the reader back to the same `#find-a-fund` combobox · a second CTA to `/methodology`, or an email capture · the same button label appears twice on one page
- **`motion-safe:` added to the shadcn primitives the public pages render (Button, Badge, Table row, Tooltip, InputGroup)**: `docs/brand-and-hero.md` requires *everything* animated to be disabled under `prefers-reduced-motion: reduce`, and the vendored shadcn base ships its 150ms `transition-all` / `transition-colors` and the tooltip's enter/exit animations unguarded, so the hero's own `motion-safe:` proof-card reveal was the only motion actually honouring the rule · a global `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { transition: none; animation: none } }` in `globals.css` · the guard now lives in five component class lists that a future `shadcn add` would overwrite, and `input.tsx`, `textarea.tsx` and `dialog.tsx` are deliberately left unguarded because no public page renders them
